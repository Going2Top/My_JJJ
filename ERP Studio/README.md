# ERP Studio 智能体 ERP 操作系统 Demo

根据 `F:\ERP Agent\详细设计.docx` 实现的本地可交互 Demo。包含十二个模块、Python API、SQLite 持久化、流程与任务设计器、三维知识关系图和发票审批闭环。无需外网、模型密钥或 SAP 账户。

## 启动

需要 Python 3.10 或以上版本，**不需要安装第三方依赖**。在项目目录执行：

```powershell
python run.py
```

浏览器打开 <http://127.0.0.1:8765>。在当前电脑也可以使用：

```powershell
& 'D:\Python\python.exe' run.py
```

自定义端口或数据库：

```powershell
python run.py --port 9000 --database data/another-demo.sqlite3
```

默认仅监听本机 `127.0.0.1`。终端按 `Ctrl+C` 停止服务。运行中不要同时启动第二个同端口服务。

## 推荐演示路径

1. 运行中心默认选择“原型回放”，显示设计文档中的 24 / 186 / 3 / 2 快照。进入“发票到付款”，可浏览八条参考实例。
2. 打开 `INV-2026-0179`，点击“模拟邮件金额调整”。金额显式调整到 ¥16,500，差异为 ¥2,000 / 10.8%，新增真实保存的演示待办。普通读取详情不修改状态。
3. 回到运行中心，点击“启动联动场景”。可选择标准复核、缺少收货、写入超时、写入失败场景。
4. 新场景自动切换“联动演示”。抽屉显示邮件、发票、订单、收货、规则、Expert 建议和同一条 trace。
5. 点击“补充授权及订单证据”，保存模拟授权、修订订单及收货记录。旧待办失效，新证据重新创建复核待办。
6. 点击“批准继续”。此时实例恢复到“写入前复核”，尚未写入。
7. 点击“继续复核并模拟执行”。标准场景生成 `DEMO-...` 凭证并归档；超时场景先进入“结果待核对”，点击“核对模拟远端结果”后完成，调用次数保持为 1。
8. 点击“查看审计”检查同一实例的证据、规则、人工决定、受控模拟调用及归档记录。完成后还可以添加待审核反馈。

人工决策页初始三个待办是文档中的独立业务对象（发票 51000983、公司代码 1000 关账、客户 300184 未清项），与 0179 和历史审计案例保持独立。

## 技术与数据

- 后端：Python 标准库 `ThreadingHTTPServer`，模块化领域服务与 SQLite。
- 前端：原生 HTML / CSS / JavaScript。无需 Node、npm 或构建步骤，所有静态资源本地提供。
- 三维图：Canvas 透视投影，具有固定三维坐标、相机旋转和缩放；不是静态背景图。
- 数据库：`data/erp_demo.sqlite3`，首次启动幂等初始化，刷新或重启保留数据。右上角重置按钮可清空本 Demo 数据并恢复种子。
- 金额：整数分；金额差异与阈值：`Decimal`，差异率分母为采购订单金额，等于 2% 不算超额。
- 审批：SQLite 事务内比较版本、检查证据快照、更新待办 / 实例、追加审计 / outbox；并发审批只成功一次。
- 写入：仅模拟适配器，按实例、节点访问与批准快照计算幂等键；未知结果只核对、不自动重发。
- 版本：草稿、测试、审批、批准和激活分开；活动配置在激活之前保持原样，已有实例继续使用绑定版本。
- 作用域：本地演示只提供财务部门，服务端拒绝其他部门和审计员写入。
- 接口：`/api/v1/*`，接口一览见 [docs/API.md](docs/API.md)。事件增量读取 `/events?after=<cursor>`，与业务事务一起写入 outbox；前端轮询待办数量。

为便于直接运行，本 Demo 将详设建议的 FastAPI / PostgreSQL / Redis / React 技术栈简化为标准库服务、SQLite 和原生前端。没有 Docker 或数据库服务安装要求。

## Demo 边界

SAP、邮件、文件连接、OCR、Expert、模型填充及性能指标均为明确标记的模拟或固定数据。没有真实 MCP 协议服务、真实文件 OCR、支付、SAP 过账、企业登录、凭据管理、分布式 worker / 队列或生产级证据存储。身份切换仅用于开发演示，不是认证或生产安全边界。

流程画布编译并保存设计，但联动实例由固定发票执行骨架运行；修改任意画布不会自动生成通用业务引擎。其余七个流程提供目录与配置，不包含七套完整财务执行引擎。固定沙箱测试真实执行本地规则及证据判断，不能代表模型准确率、生产延迟或成本。

七项治理状态用于表达原型设计，已经落地的控制为上述事务、版本、权限、Expert 字段边界、幂等及审计检查；凭据过期、生产补偿等控制尚需真实集成。SQLite 审计通过应用层和触发器追加写入，尚未实现独立不可篡改存储。反馈只进入待审核案例池，不会自动学习或修改活动配置。

来源语境：详设基于 Charles 的“独立架构研究 / 概念蓝图，非产品方案”。本实现为该概念设计的本地 Demo，不代表原作者产品或已完成生产集成。
