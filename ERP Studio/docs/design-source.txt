1 使用方法与还原边界
本设计以用户提供的《智能体时代的ERP架构演进.mp4》为唯一产品参考，目标是让后续 coding agent 实现视频中可见的十二个模块及其交互，并为需要真实运行的部分提供可执行的后台方案。先交付确定性的完整演示系统，再替换模型与 ERP 适配器；不得以真实 SAP、模型账户或企业知识库尚未提供为由阻塞原型还原。
视频时长 385.30 秒，画面 1280 × 720，24 fps。已按五秒间隔提取 77 张参考画面并检查主要页面、抽屉和状态变化；随包保留 28 张关键原始分辨率截图及索引。时间戳表示采样画面所在时刻，页面切换起止为近似值，并非逐帧点击日志。本轮已完成全长音轨的自动转写，并逐段阅读转写、结合画面校核关键术语和数值；另附带时间戳的旁白解析。自动转写含术语错字，故不作为精确逐字字幕；未能从画面校核的语音细节保留不确定性。这是视听内容解析与交互还原详设，不是原产品源码的反向还原。
视频标题页明确写有“独立架构研究”“概念蓝图｜非产品方案”，作者署名 Charles。必须保留这种来源语境：视频展示概念原型，不足以证明真实模型推理、SAP 写入、审批引擎或知识图谱后台已实现。截图中模型名称、API 名称、版本和评测数字均作为原型展示数据，不作为供应商现行能力或可用 API 的证明。
1.1 证据标签
全文采用四种标签。V 表示画面明确可见；A 表示自动转写结合画面校核的旁白语义；I 表示由前后画面推断的交互或关系；D 表示为编码落地补充的设计。任何技术栈、数据库、接口、鉴权、模型 Prompt、状态机、错误恢复、响应时限及验收阈值，除特别标记外均属 D。未曝光的表单、菜单和后台不得伪称视频原功能。
优先级为 P0 画面与演示闭环、P1 生产式后台语义、P2 企业集成扩展。P0 并不等于只有静态页面：所有被展示的关键操作必须改变共享状态，刷新后可恢复；模型和外部系统可用可注入延迟与故障的模拟器。
1.2 两种运行模式
replay 模式用于对照视频。固定 1280 × 720 浏览器视口，载入视频初始快照，所有模型、外部系统和评测均使用明确标记的演示数据；只有用户点击或显式演示事件推进状态。历史示例统计允许与明细不对应，但要在开发说明中声明口径，不允许伪装成实时聚合。
integrated 模式使用同一页面、领域模型和操作接口，替换真实数据库、队列、模型和 SAP 适配器；统计统一由服务端投影计算。真实写入默认关闭。模式标识放在开发环境横幅或设置中，视觉对比截图时可隐藏横幅；不得借此把演示评测显示成真实测试结果。
1.3 最终交付与完成定义
交付完整十二模块、两类设计器、三维关系图、运行实例抽屉、人工决策、工具创建、资产审批及统一审计；至少跑通一条“供应商邮件与发票 → OCR → 三单匹配 → 规则 → 专家建议 → 人工审批 → 受控 ERP 写入 → 审计归档”的闭环。其他流程具备可浏览目录和可配置规则，不能宣称已实现八套完整财务业务引擎。
视觉相似、交互可用、业务状态一致和生产集成是四个不同验收维度。视频不足以支持“后台 1 比 1”承诺；P0 验收追求已展示画面的高保真重现。

3 产品定位与对象职责
3.1 产品目标
V：界面名称为“企业智能体工作平台 / 智能体 ERP 操作系统”，当前范围“财务 · 端到端运营”。运行中心先看流程智能体总体运行状态，进入流程后查看业务实例。人工只处理制度要求、风险和歧义，常规路径继续运行。负责人治理 KPI、人员分配、规则阈值和异常，配置更改须经审批。
I：这是面向财务负责人、流程设计者和资产治理者的运营控制台，而不是一个以聊天窗口为中心的助手。视频没有展示全局自然语言聊天页、语音入口或任意 ERP 操作的即时执行界面。不要因为“ERP Agent”而擅自在 P0 首页增加聊天框。

4.3 公共组件与行为
AppShell、SidebarNav、ScopeCard、GlobalHeader、PageHeader、StatCard、StatusBadge、CardGrid、DataTable、Tabs、PillFilter、EvidenceList、RightDrawer、Timeline、ApprovalBanner、SchemaEditor、AssetPicker、EmptyState、Toast、ErrorState 是共享组件。全页范围卡和页头部门选择都绑定 departmentId；初始只有财务选项，更多部门为扩展，不捏造画面中的部门列表。
抽屉宽约 504 px，自右侧覆盖，遮罩 rgba(15,23,42,.20)，页顶关闭按钮；正文内部滚动。Esc 和关闭按钮关闭，遮罩点击可关闭但未保存表单需先确认丢弃。打开锁背景滚动并管理焦点。Toast 黑底白字居中靠下，约 2 秒后消失，但真实操作状态不能只存在于 Toast。
所有保存、批准、发布和测试操作应有 pending、成功、失败状态。重复点击 pending 按钮禁用。筛选变化立即更新结果数；空结果给清空筛选入口。P0 演示固定延迟 300 ms；外部失败不得一直 spinner。键盘可聚焦按钮、Tab、表单和抽屉，状态不能只靠颜色表达。

复核路径 规则异常 → 专家建议 → 人工决策 → 重新校验；事实改变则重新匹配

8.3 编辑与测试操作
点击库条目插入到选中节点之后；无选中时插入到最后可编辑节点前。已有多个出边时要求选择被拆分的边，不能随意破坏条件。删除节点前显示受影响连接，保留首尾事件与必需审计节点；支持撤销/重做各 30 步。自动布局只变位置，不改条件和依赖。保存草稿自动节流 800 ms，显示保存状态，离开有未保存更改时确认。

17.3 运行状态与事件
ProcessInstance：CREATED→RUNNING，遇人工→WAITING_HUMAN，缺材料→WAITING_INPUT，外部不明结果→RECONCILING，已知失败→FAILED，可恢复错误→RETRY_WAIT，完成→COMPLETED，拒绝→REJECTED，取消→CANCELLED。展示“异常”映射 FAILED/RECONCILING，待人工只映射 WAITING_HUMAN，处理中映射 CREATED/RUNNING/RETRY_WAIT。列表计数互斥，单个实例不能同时进处理中与待人工。
NodeRun：PENDING→RUNNING→SUCCEEDED；或 WAITING_HUMAN/FAILED/RETRY_WAIT/SKIPPED。节点输出必须先 Schema 校验、再存证据与审计、再推进下一节点。工作队列至少一次投递，使用 nodeRunId + attempt 去重，不能假设 exactly-once。
主要事件 InstanceStarted、NodeStarted、EvidenceCaptured、TaskCompleted、RuleEvaluated、ExpertAdvised、HumanRequired、HumanApproved、HumanRejected、WriteRequested、WriteSucceeded、WriteOutcomeUnknown、InstanceCompleted、AssetSubmitted、AssetActivated。事件保存在 outbox，再推送 SSE 与更新统计投影。replay 事件同样通过 reducer 应用，不能直接修改 DOM 文本。
17.4 审批与写入一致性
审批提交采用 compare-and-swap：WHERE task.state=PENDING AND task.revision=expectedRevision，事务内记录决定、更新任务、更新实例、插入 AuditEvent 和 OutboxEvent。第二个审批人收到 409 REVISION_CONFLICT。审批时证据或金额变化则 412 EVIDENCE_CHANGED，旧决定不得继续授权新 payload。
写入前验证 active tool version、route version、身份 scope、已批准的业务 payloadHash、证据新鲜度、规则版本、职责分离和公司代码；任何变化重新校验/审批。幂等键按 tenantId+instanceId+nodeId+visitIndex+businessPayloadHash，不随网络重试变化。
写入结果 SUCCESS 才推进；明确失败记录外部错误码；超时后可能已成功，进入 RECONCILING，通过 SAP 业务键或 adapter 查询核对，未确认前不得自动重发。无法支持远端幂等时使用本地 invocation 锁与外部对象检索；这不能保证远端 exactly-once，需明确残余风险。凭证冲销需独立受控流程，禁止用数据库回滚假装撤销 SAP 交易。
17.5 检索与模型调用
D：固定执行骨架由流程引擎控制，模型只负责 OCR 后理解、结构化建议、配置草稿与 Expert 评估；流程不由模型自由改写。模型网关统一 timeout、token budget、schema、版本标识和结果归档。Prompt/模型配置是 AssetVersion 的一部分。前端绝不保存模型密钥。
外部邮件/附件是待处理数据，不得覆盖系统指令。检索上下文按 ACL 过滤；实体关系携带证据来源与有效期。Expert 输入分为 policy、verifiedFacts、skillResults、evidence、question，输出只能是 ExpertResult。保留简短可读理由和引用，不要求模型生成或公开内部思考过程。
模型失败、拒答、输出不合法时不能默认通过；可重试一次结构化修复，仍失败走人工。OCR 置信阈值与 Expert confidence 分开，不把两个模型分数平均当财务授权。

19 种子数据与跨页一致性
fixtures/seed.json 包含流程、八条实例、三条初始待办、任务目录、工具、连接器、图谱节点与边、KPI 展示快照、规则和评测示例，记录 observed 或 designed 来源。fixtures/scenarios.json 给出事件序列。不能从截图里对没有出现的数据作真实业务推断。
两组数据必须区分。业务列表 0179 是异常详情演示；人工决策初始第一条对象是发票 51000983，不是 INV-2026-0179；审计案例 AP-2026-0731-014 也未被视频证明是同一个实例。P0 可在各页展示这些独立固定场景，禁止仅因同属“发票到付款”就合并 ID。闭环验收另用 scenario-linked-0179，显示同一实例贯穿页面，并标注它是 D 的联动场景。
演示初始快照：运行中心 24/186/3/2；发票工作列表 4/2/1/1；待决队列 3；八流程目录；工具 8/4/4/2/99.24；SAP 8/7/6/2/12；看板保持视频值。调用 resetDemo 恢复所有 IndexedDB 记录、版本、事件和 viewport，不只刷新当前页面。
integrated 一致性不变量：部门待人工数等于 WAITING_HUMAN 实例去重数，待办数可因多人审批多于实例数但须明确口径；实例四类数之和等于筛选全集；批准只减少有效待办；完成后等待数不再保留；发布前旧版本生效；未授权用户无法查看跨部门证据；一个业务对象的同一受控写入幂等键只对应一个有效外部结果。
20 非功能与部署
D 验收目标而非视频实测：本机演示首屏可交互 ≤3 秒，筛选和抽屉响应 ≤300 ms（不计注入模拟延迟）；1280 ×720 下普通页滚动流畅、12 节点图谱拖拽 ≥30 fps、100 节点流程设计基本交互 ≤100 ms。生产容量没有业务负载输入，本设计不承诺 TPS。先提供每租户 10 个并行流程 worker 的可配置默认，压测后调整。
本地一条启动命令启动 web/api/postgres/redis/object-store，.env.example 只给变量名，默认 DEMO_MODE=true、ERP_WRITE_ENABLED=false。无外网、无模型密钥时 P0 可完整运行。数据库迁移和 fixtures 以幂等 seed 脚本导入，测试与开发隔离。日志默认去敏，不记录附件全文、凭据或银行账号；traceId 串起请求、任务、证据与审计。
对象存储链接需短期授权，不把永久公开 URL 存进页面。生产数据库备份与恢复、队列重放、未完成实例恢复需有运维手册。未知远端写入结果单独告警并禁止自动清理。队列死信保留 instance/node/attempt/error，重放必须保留原写入幂等键。
21 Coding Agent 实施顺序
21.1 阶段 A 高保真可交互原型

21.2 阶段 B 持久化与流程闭环

21.3 阶段 C 模型与企业集成
接 OCR/LLM 网关、真实知识检索、真实 Connector 与 SAP sandbox。先读取、再模拟写、最后受控写；每个工具独立契约测试与财务语义确认。通过审批与安全测试后才启用生产写入，不能用“接了一个大模型”替代治理引擎。

24 给 Coding Agent 的执行指令
